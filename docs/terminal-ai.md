# ローカル端末とAI/MCP

開発ブランチの機能です。外部サービスの契約と利用料は利用者自身が管理します。

## CMDとSSHを並べる

Windows 10 1809以降で「ファイル → ローカルCMDを開く」を使えます。
SSHタブの「W端末」でSSHとCMDを同じ画面に配置します。
CMDを隠してもプロセスは継続し、タブを閉じると、そのタブが開始したプロセスを終了します。
SSHの再接続はCMDに影響しません。開始フォルダと対話操作後の現在のフォルダは区別します。

## AI相談

「表示 → AI相談」で共有端末と実行モードを選びます。初期状態では共有しません。
「相談のみ」は読取り、「毎回確認」は操作ごとの承認、「指定端末で自動実行」は選択した端末の
操作を許可します。許可は15分で失効し、再接続後には選び直します。
「停止・許可を取り消す」、対象の変更、パネルを閉じる操作で許可を取り消します。
独立実行の中止はSSHサーバー側のプロセス終了まで保証できません。
対話入力は送信結果を返し、終了コードを推測しません。

「AI接続設定」でOpenAI、Anthropic、互換APIのキーとモデルを指定します。
キーの保存は明示的に選択します。ChatGPTのプラン接続は専用の公式OAuthログインを使い、
アカウントごとに取得した利用可能モデルから選びます。APIキーとは別に管理します。
「送信内容を確認」で送る端末情報を編集できます。既知の秘密情報をマスクしますが、
すべての秘密情報を自動検出できるわけではありません。

## MCP接続

「表示 → MCP接続設定」で現在のHashiに接続するstdio設定を生成します。
AI相談で端末とモードを選び「AI/MCP共有を適用」すると、APIキーを設定せずに利用できます。
共有許可と操作履歴は組み込みAIと共通です。

MCPクライアントに表示されたJSONを設定します。接続設定はHashiの起動中だけ有効です。
再起動時は生成し直してください。ほかのHashiの接続設定は使えません。
「MCP接続を停止」で接続経路を閉じ、進行中のHashi経由の操作を取り消します。

配布ファイルでは`Hashi.exe`と`HashiMCP.exe`を同じフォルダに置いてください。
ヘルパーはJSON-RPCだけをstdoutに出し、GUIとは127.0.0.1の認証付きIPCで通信します。
HTTPは公開せず、接続情報をユーザー限定の一時フォルダに置き、終了時に削除します。
開発環境ではPythonヘルパーの絶対パスを設定し、インストール済みパッケージでは
`hashi-mcp <接続情報ファイル>`も利用できます。

参照: [MCP stdio仕様](https://modelcontextprotocol.io/specification/2025-11-25/basic/transports)
