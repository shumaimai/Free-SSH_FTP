# ローカル端末とAI/MCP

開発ブランチの機能です。外部サービスの契約と利用料は利用者自身が管理します。
[監査対応・検証手順](terminal-ai-audit.md)に実装の確認先と未検証の項目を記載しています。

## CMDとSSHを並べる

Windows 10 1809以降で「ファイル → ローカルCMDを開く」を使えます。
SSHタブの「W端末」でSSHとCMDを同じ画面に配置します。
CMDを隠してもプロセスは継続し、タブを閉じると、そのタブが開始したプロセスを終了します。
SSHの再接続はCMDに影響しません。開始フォルダと対話操作後の現在のフォルダは区別します。

## AI相談

「表示 → AI相談」を開き、「AIに接続…」で接続します。画面は「会話」「対象端末」「実行履歴」の3つです。
一般的な質問は「会話」に入力して送信できます。端末を見せる場合は「対象端末」でチェックし、
「この端末を共有する」を押します。接続先と共有状態は上部に表示します。初期状態では共有しません。
「読むだけ」は読取り、「操作ごとに確認」は操作ごとの承認、「選択した端末で自動実行」は選択した端末の
操作を許可します。許可は15分で失効し、再接続後には選び直します。
「停止する・端末の共有を解除」、対象の変更、パネルを閉じる操作で許可を取り消します。
独立実行の中止はSSHサーバー側のプロセス終了まで保証できません。
独立CMDが先に終了し、子プロセスが出力を保持している場合は、出力完了を「不明」と返します。
明示的に切り離したバックグラウンド処理の終了は、操作の停止だけでは保証しません。
対話入力は送信結果を返し、終了コードを推測しません。

「AIに接続する」でOpenAI、Anthropic、Command Code、その他の互換APIを選びます。
APIキーを入力して「モデル一覧を取得」から選ぶか、利用可能なモデル名を入力します。
「接続を確認」は短い回答を取得するため、提供元の利用料が発生します。「この接続を使う」で会話へ戻ります。
Command Codeは公式の`https://api.commandcode.ai/provider/v1`を使用し、モデル一覧の対応形式から
Chat Completions / Responses / Anthropic Messagesを選びます。個別のエンドポイントURLを貼っても正規化します。
手入力のClaudeモデルはMessagesを使います。その他の互換APIでは形式を明示指定できます。
保存・削除の失敗は理由を画面に表示し、ダイアログを閉じずに再試行できます。
キーの保存は明示的に選択します。ChatGPTのプラン接続は専用の公式OAuthログインを使い、
アカウントごとに取得した利用可能モデルから選びます。APIキーとは別に管理します。
「送信内容を確認」で送る端末情報を編集できます。既知の秘密情報をマスクしますが、
すべての秘密情報を自動検出できるわけではありません。
互換APIが端末ツールに対応しない場合は、接続設定のツール利用を外して助言だけ受けられます。

## MCP接続

「表示 → MCP接続設定」またはAI相談の「対象端末 → ほかのMCPクライアントを接続…」で
現在のHashiに接続するstdio設定を生成します。
Hashi側で有効にするだけではクライアントへ接続されません。stdioを起動できるMCPクライアントに設定してください。
この設定をクラウドのChatGPTへ貼り付けるだけでは、クライアントPCへ接続できません。
AI相談の「対象端末」で端末とモードを選び「この端末を共有する」と、APIキーを設定せずに利用できます。
共有許可と操作履歴は組み込みAIと共通です。

MCPクライアントに表示されたJSONを設定します。接続設定はHashiの起動中だけ有効です。
再起動時は生成し直してください。ほかのHashiの接続設定は使えません。
「MCP接続を停止」で接続経路を閉じ、進行中のHashi経由の操作を取り消します。

配布ファイルでは`Hashi.exe`と`HashiMCP.exe`を同じフォルダに置いてください。
ヘルパーはJSON-RPCだけをstdoutに出し、GUIとは127.0.0.1の認証付きIPCで通信します。
HTTPは公開せず、接続情報をユーザー限定の一時フォルダに置き、終了時に削除します。
開発環境ではPythonヘルパーの絶対パスを設定し、インストール済みパッケージでは
`hashi-mcp <接続情報ファイル>`も利用できます。

参照: [MCP stdio仕様](https://modelcontextprotocol.io/specification/2025-11-25/basic/transports)

## 公式CLIをHashi内で起動

AI相談の「Claude Codeを開く」または「ファイル → 公式CLIを開く（Claude Code）」で開きます。
導入済みのWindowsネイティブ版`claude.exe`はPATHと既定の導入先から検出し、対応機能を確認します。
未導入なら公式の`https://claude.ai/install.ps1`を変更せずダウンロードして、通常のユーザー権限で実行します。
公式インストーラーがstable版の取得・検証・導入を行います。キャンセルするとHashiが開始した導入プロセスを終了します。
導入確認後、起動フォルダを選んで「Claude Codeを開く」を押します。npm/WSL版の埋込み起動には対応していません。

本人のログインは公式CLIで行います。認証情報の管理と請求は公式CLIと本人の契約に任せます。
Hashi独自のAI相談でClaudeのサブスクOAuthは使いません。独自AI相談のAnthropic接続はAPIキー方式です。
公式CLIの画面・入力はHashiのAIコンテキストとログ保存の対象外です。
公式CLI自身の履歴保存は公式CLIの設定に従います。

起動ごとのMCP設定を渡し、既存のCLI設定ファイルを上書きしません。
標準の「通常のClaude Code（本人の設定を使う）」では、公式CLIの内蔵ツール・ユーザー設定・フックを使います。
「Hashiの共有端末だけを使う」を選ぶと、この起動のツールとMCPをHashiへ限定できます。
ユーザーフックを無効にする選択肢は別にあります。
管理者設定・管理者フックは引き続き適用されるため、HashiがCLI全体の操作を制御するわけではありません。
内蔵ツールやユーザーフックを有効にする場合、それらの操作はHashiの実行管理を通りません。
CLI側で必要な承認はCLIで行い、MCP操作にはHashi側の対象範囲・実行モードも適用します。
AI相談の操作履歴で実行先ID・世代・状態・終了コードを確認できます。本文と出力は履歴へ保存しません。

「Hashi経由の操作を停止」はMCP操作を取り消し、共有許可を解除します。
「CLIへCtrl+Cを送る」は公式CLIへの対話入力です。タブを閉じるとCLIプロセスを終了します。
再開は起動ダイアログの「前回のCLI会話を再開」または公式CLIの再開機能を使います。
MCP接続を停止・再生成した場合、公式CLIタブを開き直してください。
